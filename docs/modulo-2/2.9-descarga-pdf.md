# 2.9 — Descarga PDF generada por servidor

## Alcance y dependencias

Dompdf3.x convierte una plantilla Blade fija a PDF A4. Instalar mediante Composer:

```
composer require "dompdf/dompdf:^3.1"
```

El paquete no reemplaza composer.json ni composer.lock; Composer actualiza los archivos del proyecto preservando el resto de sus dependencias. Incluir ambos cambios en el commit posterior. No se modifica.envni se agregan migraciones. Documentación oficial:https://github.com/dompdf/dompdf.

## Rutas protegidas

- GET /finanzas/comprobantes/{source}/{operationId}/pdf:propietario de la wallet autenticada; reutiliza exactamente la resolución de datos del detalle personal.
- GET /finanzas/caja/asociaciones/{associationId}/receipts/{receiptId}/pdf:permiso readde Caja en la asociación real; reutiliza snapshot existente y folio. No accede a caja mediante permiso genérico de la web.
- GET /finanzas/comprobantes-administracion/pdf?source=...&operation_id=...&wallet_id=...:misma validación,2FA, actor y contexto de la consulta administrativa. La URL de descarga utiliza la consulta que produjo el resultado mostrado, no los campos editados posteriormente.

Las nuevas rutas están en las mismas agrupaciones web/auth/verified/session.active/device.track, con throttle20/minuto. No agregan una API PDF de servicios ni cambian el contrato de delegación de la API personal. El generador recibe únicamente DTO/snapshot autorizados del servidor; no admiteHTML, archivos oURLs del cliente.

Se conserva Imprimir/guardarPDF del navegador. Se añade DescargarPDF con enlace normal para recibir attachment, no navegación Inertia ni lectura de documentos desde rutas públicas.

## Archivo

Content-Type:application/pdf, Content-Disposition:attachment con nombre que contiene ID normalizado, Cache-Control:private/no-store y X-Content-Type-Options:nosniff. Renderizado en memoria, sin guardar PDF en carpeta pública o storage compartido. Se usa una carpeta privada de caché/t temporales del motor en storage/framework/cache/receipt-pdf. Esa carpeta no guarda historial financiero y debe ser escribible por PHP.

Fuente DejaVuSans para acentos. Plantilla sin imágenes remotas ni recursos personalizados; Dompdf desactiva PHP,JavaScript y recursos remotos, con chroot al directorio de su librería. Campos se escapan mediante Blade{{}}. Los importes se formatean desde centavos usando separación decimal de strings, evitando convertir centavos grandes a flotante para presentación. Fechas etiquetadasUTC. La fecha de generación no sustituye la fecha de operación.

Documento incluye ID,estado,moneda,fecha,desglose de wallet/bonos, movimientos de la participación autorizada y folios de caja existentes. Mantiene aviso de recarga histórica revisada sin evidencia de recepción en caja cuando corresponde. No incluye cuenta/motivo interno de revisión ni secretos, tokens, claves de idempotencia o saldos de otras wallets. No constituye factura ni firma digital. No se crea nuevo folio y una descarga repetida no liquida de nuevo una operación.

El PDF de Caja muestra caja/asociación, flujo y folio del snapshotguardado. Los controles especiales actuales de supervisor/estudiante permanecen en los servicios originales; el PDF no los reemplaza. El detalle de auditoría histórica es una pantalla distinta de los comprobantes; no se añadió exportación de auditoría en esta entrega.

## API explicada

La web personal identifica al usuario mediante sesión. La API /api/v1/financial/receiptspermite a otra aplicación consultar los comprobantes. Un token con financial:receipt:readidentifica a esa aplicación y autoriza el tipo de petición, pero no demuestra permiso para consultar a un estudiante. X-User-Authorizationdebe demostrar delegación del usuario y vincular cliente,acción y petición. ReceiptDelegationProviderverifica ese contrato; el proveedor pendiente devuelve503sin acceder a la wallet. Esto no bloquea las rutas web de descarga PDF, que ya tienen sesión/propiedad o permiso administrativo comprobados. Conectar el proveedor oficial no obliga a cambiar los endpoints existentes.

## Validación

Seis pruebas nuevas:sesión/propiedad,PDFreal y ausencia de escritura financiera,pago100%conbonos,escapeHTMLyaviso,autorización administrativa/2FA,PDFdeCaja con permiso y folio conservado. Verifican cabeceras, firmaPDFyfinalEOF del archivo generado porDompdf. No se ejecutaron aquí por ausencia dePHP/SQL/Mongo. La sintaxisVuepasó. Revisar además un PDF descargado en el navegador para comprobar el resultado real de fuentes,márgenes y textos antes de commit. La plantilla no se presenta como visualmente certificada hasta esa revisión.
