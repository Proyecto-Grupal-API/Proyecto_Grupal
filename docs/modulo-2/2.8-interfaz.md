# 2.8 — Interfaz de caja conectada a servicios y autorización

Base: 1374082, con siete pruebas API verificadas y 316 pruebas financieras / 2309 aserciones. Agrega la página /finanzas/caja y diez endpoints web equivalentes a la API, además del contexto de permisos. No requiere migraciones nuevas ni modifica .env.

## Navegación y pantalla

Finanzas se agrega al menú principal y móvil. Mi wallet incorpora Caja y turnos junto a los enlaces 2.7 y 2.10. La página conserva colores y layout del proyecto.

El usuario introduce el identificador externo de su asociación y consulta sus cajas. No se enumeran asociaciones globalmente: el catálogo confiable de Módulo 6 aún no está integrado. Se seleccionan caja y turno, se consultan efectivo inicial/entradas/salidas/ajustes/esperado, arqueo cerrado e historial paginado. Listados de diez registros con navegación anterior/siguiente; las rutas admiten el límite de paginación existente.

Operaciones: abrir turno con fondo inicial; recarga o retiro en efectivo con UUID de wallet, importe y motivo; entrada o salida física; ajuste positivo o negativo; cierre con efectivo contado y motivo. Los importes del formulario están expresados en la moneda de la caja, se convierten a centavos mediante procesamiento decimal exacto y se rechazan más de dos decimales. El servidor vuelve a validar todos los valores.

Antes de enviar se confirma el efectivo físico. Cada solicitud genera una clave idempotente. Durante el envío se bloquean formularios y navegación. Si falta respuesta o hay conflicto, se conserva URL, payload y clave; el reintento usa exactamente la misma solicitud. Descartar un reintento requiere confirmar que se revisará el historial: no cancela ni revierte una operación. Tras validación/acceso fallido se pueden corregir campos; tras respuesta exitosa se renueva el formulario y se actualiza historial/resumen. Si falla la actualización después de éxito se informa que la operación sí fue confirmada.

## Seguridad y reutilización

CashWebController extiende CashController; reutiliza consultas filtradas por asociación, validación, claves, DTOs y servicios de caja. El único cambio en CashController es hacer protected el serializador de turno para añadir is_operator en las respuestas web. La API OAuth no recibe ni depende de esa propiedad.

FinancialWebActor obtiene user:<ID de la sesión>. No se crea un token OAuth del usuario ni se acepta actor del payload. API conserva service:<ID del cliente>. La sesión web requiere auth, verified, session.active y device.track; mantiene CSRF en producción. La página principal no carga datos financieros de asociaciones. /finanzas/caja/context devuelve únicamente association_id y los cuatro booleanos de permisos.

CashAuthorizationProvider es el mismo contrato del bloque API. read, operate, adjust y close se comprueban en cada llamada del servidor. UUID fuera de asociación autorizada: 404; asociación sin concesión o cajero ajeno: 403. Movimientos/recargas/retiros requieren operador responsable; ajuste/cierre admiten un supervisor autorizado de esa asociación. Los botones deshabilitados son ayuda visual; no sustituyen autorización.

PendingCashAuthorizationProvider sigue denegando todas las concesiones. Por eso la página se puede visitar y consultar contexto, pero no muestra cajas ni habilita operaciones hasta integrar el adaptador confiable de Módulos 1/6. No habilitar User.roles históricos ni introducir un proveedor que conceda todo para demostrar la pantalla. El formulario queda conectado sin necesitar reemplazo cuando el adaptador real esté disponible.

## Rutas

GET /finanzas/caja: página.
GET /finanzas/caja/context?association_id=...: permisos para actor de sesión.
Prefijo de datos: /finanzas/caja/asociaciones/{associationId}

| Método | Ruta | Permiso |
|---|---|---|
| GET | /registers | read |
| GET | /registers/{registerId}/shifts | read |
| GET | /shifts/{shiftId} | read |
| GET | /shifts/{shiftId}/movements | read |
| POST | /registers/{registerId}/shifts | operate |
| POST | /shifts/{shiftId}/movements | operate |
| POST | /shifts/{shiftId}/topups | operate |
| POST | /shifts/{shiftId}/withdrawals | operate |
| POST | /shifts/{shiftId}/adjustments | adjust |
| POST | /shifts/{shiftId}/close | close |

POST conserva Idempotency-Key obligatorio. Éxito 200; validación 422; conflicto 409; token de servicios no concede acceso a estas rutas de sesión. No se duplican movimientos ni se añade una transacción externa que suprima evidencia de límites.
