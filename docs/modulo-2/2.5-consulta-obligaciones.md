# 2.5 · Consulta y conciliación de obligaciones institucionales

Base E2: 3b741c1. Consulta operativa de solo lectura sobre el estado actual. No emite bonos, mueve fondos, modifica deudas, crea wallets, liquida o repara diferencias. No agrega rutas, permisos o interfaz. No cambia .env ni requiere npm build o migraciones nuevas.

## Uso

```powershell
php artisan financial:institutional-obligations
```

Lista la primera página de presupuestos con su conciliación. Usa budget_id de la salida para consultar un presupuesto completo y sus grupos de negocio:

```powershell
php artisan financial:institutional-obligations --budget="UUID_DEL_PRESUPUESTO"
php artisan financial:institutional-obligations --budget="UUID_DEL_PRESUPUESTO" --business="NEGOCIO_REAL"
php artisan financial:institutional-obligations --budget="UUID_DEL_PRESUPUESTO" --details
php artisan financial:institutional-obligations --budget="UUID_DEL_PRESUPUESTO" --page=2 --per-page=10
```

Reemplazar los valores descriptivos por identificadores existentes; no ejecutar el texto UUID_DEL_PRESUPUESTO literalmente. Sin presupuestos devuelve status NO_DATA, consistent null y listas vacías. No es un error ni una autorización para crear presupuesto por fuera del flujo aprobado.

Con budget, page/per-page paginan grupos de negocio o detalles. Sin budget, paginan presupuestos. per-page admite 1 a 20, por defecto 10. business y details requieren budget. has_more indica que debe consultarse otra página. No se infieren resultados de páginas no observadas.

La conciliación de cada presupuesto siempre incluye todos sus negocios. business filtra únicamente entries; una diferencia en otro negocio sigue haciendo que el presupuesto devuelva DIFFERENCES. No comparar el subtotal filtrado con el consumido del presupuesto entero.

## Significado de los importes

Cada presupuesto muestra aprobado, comprometido y consumido; las obligaciones muestran importe original de compras, devoluciones registradas y pendiente neto. El detalle incluye UUID de obligación, compra y bono, negocio, moneda e importes. No imprime identidad humana, email, credenciales, referencias de consentimiento o el cuerpo de eventos.

Los importes y contadores de cantidades se devuelven como strings decimales exactos en centavos. No convertirlos a float ni sumarlos mediante JavaScript Number. Las sumas se realizan en SQL Server con DECIMAL(38,0); incluso el volumen bruto acumulado puede superar PHP_INT_MAX sin perder precisión. Monedas permanecen separadas en los grupos; no se convierten tipos de cambio.

Pendiente es amount_cents menos refunded_amount_cents, no un saldo de wallet. Esta fase aún no implementa liquidación: no existe un pago institucional certificado que deba restarse. Las devoluciones pendientes o aprobadas sin ejecución no disminuyen la deuda.

Ejemplo: BECA 3000 centavos; compra 1000; devolución ejecutada 400. Comprometido 2400, consumido y deuda neta 600. Al cancelar/vencer el remanente, comprometido pasa a cero; la deuda de 600 permanece.

## Comprobaciones

El reporte contrasta consumido presupuestario contra obligación neta y contra consumos menos devoluciones del ledger. Compara comprometido contra saldos institucionales registrados y contadores de devolución contra evidencia inmutable. No descarta un bono con marcador roto si lo referencia su compromiso original u obligación.

Los findings incluyen códigos estables de diagnóstico, cantidades cuando corresponde y hasta cinco UUID de ejemplo. Los ejemplos no son la lista completa. Detecta vínculos de emisión rotos, obligación que no corresponde a compra/negocio/pagador, compra sin obligación, devolución completada sin evidencia o con transacción/reparto inválidos, movimientos faltantes y secuencias de saldo inconsistentes. Los códigos describen discrepancias observadas; no atribuyen intención o fraude.

| Código | Diferencia observada |
|---|---|
| CONSUMED_VS_OBLIGATIONS | Consumido y deuda neta no coinciden |
| CONSUMED_VS_LEDGER | Consumido y movimientos netos no coinciden |
| COMMITTED_VS_BONUS_BALANCES | Comprometido y saldo de bonos no coinciden |
| REFUND_COUNTER_VS_EVIDENCE | Contador de devoluciones y evidencia no coinciden |
| BONUS_BINDING | Vínculo de bono, compromiso o emisión inválido |
| OBLIGATION_EVIDENCE | Compra, negocio, pagador o evidencia de obligación inválidos |
| PURCHASE_WITHOUT_OBLIGATION | Compra institucional sin su obligación |
| REFUND_EVIDENCE | Evidencia de devolución/transacción/reparto inconsistente |
| LEDGER_RUNNING_BALANCE | Saldo por movimiento fuera de rango o incorrecto |
| BONUS_VS_LEDGER_BALANCE | Saldo del bono diferente de su ledger o ledger ausente |
| OBLIGATION_WITHOUT_MOVEMENT | Falta el movimiento único de consumo correspondiente |

| COMPLETED_REFUND_WITHOUT_EVIDENCE | Devolución completada sin registro institucional |
| BUDGET_CURRENCY | Presupuesto con obligaciones en moneda incompatible con esta fase |

## Consistencia y límites

Se toman locks compartidos HOLDLOCK sobre los presupuestos seleccionados dentro de una transacción sin escrituras. Coordinan con los escritores institucionales existentes, que bloquean primero el presupuesto antes de tocar bonos, obligaciones y movimientos. No se solicitan UPDLOCK ni se modifican tablas de locks. La lectura puede esperar o hacer esperar brevemente a un escritor del mismo presupuesto.

basis COORDINATED_CURRENT_READ no es un snapshot histórico ni una garantía ante escrituras directas que ignoren ese protocolo. No se cambia el nivel de aislamiento de la conexión ni la configuración de SQL Server. Un error de consulta impide emitir un resultado conciliado. El reporte no sustituye las validaciones del writer, auditorías de infraestructura o certificación del financiamiento. Una manipulación coordinada de todas las fuentes o evidencia borrada sin referencias sobrevivientes necesita controles independientes; no se declara detectada por este reporte.

La salida está acotada por páginas; la validación recorre la evidencia SQL de los presupuestos seleccionados. No se certifica latencia con historiales extensos ni se toma la pantalla como autorización de pago. Para inspección normal usar un budget específico. No ejecutar reparaciones automáticas a partir de diferencias.

El comando es para operadores con acceso al host y a la base. No es una API pública ni un permiso de lectura concedido a alumnos o negocios. Una futura pantalla deberá aplicar autorización de lectura específica y limitar su ámbito.

## Estados y códigos de salida

- 0: consulta completada; CONSISTENT para los presupuestos observados o NO_DATA.
- 2: consulta completada con DIFFERENCES. No implica que el comando haya reparado o movido dinero.
- 1: filtros inválidos o consulta no completada. No hay certificación parcial. El error no muestra SQL ni credenciales.

No hay registro persistente de ejecuciones en esta entrega: observed_at identifica la observación, no una auditoría histórica guardada. El JSON puede conservarse manualmente por un operador autorizado.

Se incluyen 16 pruebas de lectura, conciliación real con compra/devolución, aprobación sin efecto monetario, liberación del remanente, discrepancias, paginación y filtros, referencias sin identidad, CLI, precisión por encima del rango entero y exclusión del histórico no institucional. Los datos corruptos se crean únicamente dentro de las pruebas aisladas para verificar detección; nunca se recomienda replicarlos en desarrollo.
